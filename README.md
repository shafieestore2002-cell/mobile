# شفیعی استور

فروشگاه نمایشی فارسی و راست‌به‌چپ با طراحی واکنش‌گرا، جست‌وجو و فیلتر محصولات، مرتب‌سازی، جزئیات محصول، علاقه‌مندی‌ها و سبد خرید محلی. قیمت‌ها نمونه‌اند و ثبت سفارش یا پرداخت واقعی فعال نیست. انتخاب‌های کاربر در مرورگر ذخیره می‌شوند.

## اجرا

در این محیط، دستور زیر را اجرا و نشانی `http://127.0.0.1:8000` را باز کنید:

```bash
python3 -m http.server 8000 --bind 127.0.0.1 --directory /workspace/mobile
```

صفحهٔ اصلی `index.html` است. مسیر قبلی `shafiee-advanced.html` به آن هدایت می‌شود. برنامه ایستا است؛ به مرحلهٔ build یا Node.js وابسته نیست. برای اجرای ماژول‌های جاوااسکریپت از سرور HTTP استفاده کنید.

## فایل‌ها و دارایی‌ها

- `assets/css/store.css`: ظاهر، چیدمان و واکنش‌گرایی.
- `assets/js/app.js`: جست‌وجو، فیلترها، پنجره‌ها، علاقه‌مندی‌ها و سبد خرید.
- `assets/js/catalog.js`: داده‌های کاتالوگ نمایشی؛ مرجع دادهٔ واقعی فروشگاه نیست.
- `assets/images/`: تصاویر ارسالی، دسته‌بندی‌شده و محلی. [راهنمای تصاویر](assets/README.md) و [فهرست نگاشت تصاویر](assets/image-manifest.json) مسیرها و جزئیات فایل‌ها را ثبت می‌کنند؛ پوشهٔ تصاویر اولیه حفظ شده است.
- `assets/fonts/`: دو فایل کوچک WOFF2 از Vazirmatn، بستهٔ Fontsource نسخهٔ `5.3.0`، با [مجوز OFL](assets/fonts/OFL.txt).
- `tests/test_storefront.py`: آزمون‌های مرورگر برای رفتارهای اصلی فروشگاه.

تصاویر و فونت‌های مورد استفادهٔ فروشگاه از همین مخزن بارگذاری می‌شوند و اجرای صفحه به CDN نیاز ندارد. کارت‌های مک، آیپد و اپل واچ پیش‌نمایش خانوادهٔ محصول هستند و یک SKU مشخص را معرفی نمی‌کنند.

## آزمون

در ریشهٔ مخزن اجرا کنید:

```bash
cd /workspace/mobile
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

بستهٔ Python مربوط به Playwright و مرورگر Chromium در این محیط نصب شده‌اند. آزمون‌ها Chromium را از `/usr/bin/chromium` اجرا می‌کنند، سرور موقت خودشان را می‌سازند و درخواست‌های بیرونی مرورگر را مسدود می‌کنند؛ نیازی به سرور از پیش اجراشده نیست. در محیط دیگر، این دو ابزار پیش‌نیاز اجرای آزمون‌ها هستند. نتیجهٔ معتبر، خروجی اجرای همین دستور روی نسخهٔ فعلی است.

برای تکمیل فروشگاه واقعی، [کارهای باقی‌مانده](ROADMAP.md) را ببینید.

## انتشار با GitHub Pages

فایل `.github/workflows/pages.yml` با هر push به شاخهٔ `main` خروجی عمومی را می‌سازد و روی GitHub Pages منتشر می‌کند. در تنظیمات مخزن، مسیر **Settings → Pages → Build and deployment → Source** باید روی **GitHub Actions** باشد. انتشار اولیه به فعال‌بودن Pages برای مخزن نیاز دارد.

```bash
python3 scripts/build_site.py
```

خروجی در `_site/` ساخته می‌شود و فقط فایل‌های مورد استفادهٔ سایت را دارد. تصاویر مرجع، فایل‌های آزمون، اسکرین‌شات‌ها، مستندات داخلی و ویدئوهای بلااستفاده در خروجی انتشار قرار نمی‌گیرند. دستور ساخت می‌تواند خروجی تولیدشدهٔ خودش را دوباره بسازد؛ پوشهٔ از قبل موجود و نامرتبط را پاک نمی‌کند. همهٔ تصاویر اصلی و کتابخانهٔ کامل آن‌ها در مخزن حفظ می‌شوند.
